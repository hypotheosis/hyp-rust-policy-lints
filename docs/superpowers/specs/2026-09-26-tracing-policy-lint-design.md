# hyp_tracing: require `#[tracing::instrument]` on every function

**Date:** 2026-09-26
**Status:** Approved design, not yet implemented

## Purpose

Add a second policy to the lint library: **every non-test function must be
instrumented with `#[tracing::instrument]`**, so that each call emits a span.
Exemptions are allowed, but each one must carry a written justification — the
same contract `hyp_hegel` applies to `non_hegel_test`.

Some consuming workspaces are tools that do not use tracing at all. Those turn
the policy off for the whole workspace with one justified entry in
`dylint.toml`.

## Non-goals

- Accepting hand-written spans (`info_span!(..).entered()`,
  `.instrument(span)`) as a substitute for the attribute. Only
  `#[instrument]` satisfies the lint; anything else takes an `allow`.
- Checking the *content* of the instrumentation (`skip`, `fields`, `level`,
  `err`, `ret`). Presence is the policy.
- Checking test code. Tests are not production call paths.
- Judging the quality of a justification. As with `hyp_hegel`, only a
  non-empty, non-whitespace `reason` is required.

---

## 1. Packaging

A new crate, `lints/hyp_tracing`, next to `lints/hyp_hegel`. The README's rule
applies: unrelated policies get their own library. The workspace's
`members = ["*"]` and consumers' `pattern = "lints/*"` pick it up with no
other change.

```
lints/hyp_tracing/
├── Cargo.toml
├── src/
│   ├── lib.rs            # register_lints: init_config, lints, pass
│   ├── config.rs         # dylint.toml schema + load
│   ├── instrument_detect.rs  # "is this body from #[instrument]?"
│   └── tracing_fns.rs    # the LateLintPass
├── tests/ui.rs           # one #[test] per dylint.toml scenario
├── ui/                   # default config
├── ui_disabled/          # enabled = false, reason given
├── ui_disabled_no_reason/
├── ui_disabled_blank_reason/
└── ui_bad_config/        # unknown key
```

### 1.1 One version for the whole workspace

A tag `vX.Y.Z` selects every library under `lints/`, so the crates cannot
version independently. `version` moves to `[workspace.package]` in
`lints/Cargo.toml`, both crates use `version.workspace = true`, and
`[workspace.metadata.release]` gains `shared-version = true` so cargo-release
bumps them together and cuts a single `v{{version}}` tag. The `justfile`'s
version read (currently `hyp_hegel`'s) stays correct because both crates
report the same version.

### 1.2 Dependencies

- `clippy_utils`, `dylint_linting` (workspace).
- `serde` with `derive`, for the config struct.
- Dev: `dylint_testing`, and the real `tracing` crate from crates.io. There is
  no stub: the detection depends on how `tracing-attributes` actually assigns
  spans, and a stub would test the stub. The `ui.rs` harness locates the
  `tracing` rlib the same way `hyp_hegel`'s locates `hegel`.

## 2. Lints

Both are **Deny**, consistent with `hyp_hegel`.

| Lint | Fires on |
|---|---|
| `uninstrumented_fn` | An in-scope function (§3) whose body was not produced by `#[tracing::instrument]` |
| `instrument_exemption_without_justification` | An `allow(uninstrumented_fn)` with no `reason`, or an empty/whitespace-only one; **or** a `dylint.toml` disable with no `reason`, or an empty/whitespace-only one |

`uninstrumented_fn` is **not** `report_in_external_macro`. A function
generated by another crate's macro has no source line where a consumer could
write `#[instrument]`, and builtin derives (`Debug`, `Clone`, …) would
otherwise fire on every derived method.

`instrument_exemption_without_justification` **is** `report_in_external_macro`,
for the same reason `hegel_exemption_without_justification` is: the `allow`
attribute may be written by a macro.

## 3. Scope: which functions

A function is in scope if it has a body and is one of:

- a free `fn` item (including one nested inside another function's body),
- an inherent method,
- a trait-impl method,
- a trait method with a default body.

Out of scope:

- **`const fn`.** `#[instrument]` cannot be applied to one.
- **Closures.** They are not functions a consumer can annotate.
- **Trait methods without a body**, and foreign (`extern`) function
  declarations. There is nothing to instrument.
- **Any compilation built with `--test`** (`sess.opts.test`). The whole pass
  returns early. This excludes `#[test]` functions, `#[cfg(test)]` helpers and
  every integration-test crate in one rule. Production code is still checked
  in the ordinary lib/bin compilation. `--all-targets` compiles both, and a
  run without `--all-targets` still checks production code, so this lint does
  not share `hyp_hegel`'s dependence on that flag.

Implementation: `check_fn` with `FnKind::ItemFn` / `FnKind::Method`, skipping
`FnKind::Closure`, and reading `constness` off the `FnHeader`.

## 4. Detection

A spike against `tracing-attributes 0.1.31` on this nightly
(`-Zunpretty=expanded,hygiene`) showed:

- The rebuilt signature (`pub fn sync_fn(x: u32) -> u32`) keeps the consumer's
  own tokens, so it sits in the **root** syntax context. The expansion chain
  of `def_span` therefore does *not* reveal the attribute. The technique that
  `hyp_hegel`'s `expansion_chain_includes_hegel` uses on `def_span` would give
  a false negative here.
- The generated body (`let __tracing_attr_span; let __tracing_attr_guard; …`
  for sync functions, `let __tracing_instrument_future = …` for async ones)
  sits in the context of the expansion `Macro(Attr, "tracing::instrument")`.

So a function counts as **instrumented** if any expression or `let` binding in
its body has a span whose expansion chain (walk `outer_expn_data().call_site`
to the root) contains an expansion whose `macro_def_id` belongs to the crate
whose `[lib]` name is `tracing_attributes`. Matching on the `[lib]` name
(`tcx.crate_name`) means renaming the `tracing` dependency does not affect
detection.

The visitor uses `nested_filter::OnlyBodies` so that it enters the coroutine
body of an `async fn`, and it stops at the first hit. For an instrumented
function the hit is the first statement, so the cost of the common case is
negligible.

The implementation phase re-runs this spike as a UI fixture. If the async
lowering, or a `#[instrument]` placed on a trait default method or an impl
method, does not match this description, the detection is adjusted before
anything else is built on it.

## 5. Exemptions

### 5.1 In source

```rust
#[cfg_attr(
    dylint_lib = "hyp_tracing",
    allow(uninstrumented_fn, reason = "called per byte in the decoder hot loop")
)]
fn decode_byte(b: u8) -> u8 { … }
```

The attribute may sit on the function, on any enclosing `mod` or `impl`, or on
the crate root. The level is resolved with
`tcx.lint_level_spec_at_node(UNINSTRUMENTED_FN, hir_id)` at the function's own
`HirId`, and diagnostics are emitted with `span_lint_hir_and_then` against that
same `HirId`. Passing the `HirId` explicitly means `#[warn]`, `#[deny]` and
`#[expect]` on the function or its parents are honoured regardless of which
node the pass happens to be visiting (the trap described in
`hegel_tests.rs::check_item`).

The decision table is the one `hyp_hegel` uses, with the `Expect` row added to both:

| Level / source at the function | Outcome |
|---|---|
| `Allow` from a source attribute, with a non-blank `reason` | accepted |
| `Allow` from a source attribute, with no `reason` or a blank one | `instrument_exemption_without_justification` at the attribute's lint-name span |
| `Allow` from the command line (`-A uninstrumented_fn`) | accepted: an operator decision |
| `Expect` from a source attribute, with no `reason` or a blank one | `instrument_exemption_without_justification` at the attribute's lint-name span, **and** `uninstrumented_fn` as below, so the expectation is still fulfilled |
| anything else | `uninstrumented_fn` at the function's `def_span`, resolved by rustc |

`#[expect(...)]` needs a reason as well (decided 2026-09-26, after review). An
`expect` silences the lint for as long as the function stays uninstrumented,
which makes it an exemption, and every exemption must be justified. The same
rule is applied to `hyp_hegel`'s `non_hegel_test` in this branch, to close the
identical gap there. `crate_without_hegel_tests` is unchanged.

### 5.2 Whole workspace: `dylint.toml`

```toml
[hyp_tracing]
enabled = false
reason = "CLI tool with no tracing subscriber; spans would go nowhere"
```

- The schema is `struct Config { enabled: bool /* default true */, reason:
  Option<String> }`, with `#[serde(deny_unknown_fields)]`.
- `register_lints` calls `dylint_linting::init_config(sess)`. `hyp_hegel`
  does not, because it has no config, and `init_config` is idempotent.
- The config is read once, in `check_crate`, with `dylint_linting::config`,
  not `config_or_default`: the latter panics on a bad value, which looks like
  an ICE to a consumer. On `Err`, the pass emits a plain error naming
  `dylint.toml` and the parse error (for example `unknown field "enable"`), and
  lints nothing else. A misspelt switch must not silently leave the policy
  on, or silently turn it off.
- `enabled = false` with a non-blank `reason`: the pass does nothing for this
  crate.
- `enabled = false` with no `reason`, or a blank one:
  `instrument_exemption_without_justification` fires **once per crate**, at
  the first character of the crate root (the span `crate_without_hegel_tests`
  uses). `uninstrumented_fn` stays suppressed. The configuration error is what
  needs fixing, and burying it under an error for every function would hide
  it.
- `reason` given while `enabled` is true or absent: accepted and ignored.
- `dylint.toml` is per workspace, located by dylint from the crate being
  compiled. A per-crate opt-out is already provided by §5.1 with a crate-level
  `#![allow(...)]`.

## 6. Known gaps

To be documented in the README:

- **Functions produced by other attribute macros are not reported.** Examples
  are the bodies `#[async_trait]` rewrites and a `#[tokio::main]` `main`.
  rustc cancels diagnostics in external macro expansions, and §2 deliberately
  does not opt out. This is a false negative.
- **Hand-written spans do not count.** A function that already opens a span
  manually still needs `#[instrument]` or an `allow`.
- **Adoption cost.** On an existing codebase the lint fires on nearly every
  function. The expected path is a justified crate-level `allow`, removed
  module by module. The alternative is `pattern = "lints/hyp_hegel"`, which
  does not load this library at all, at the price of not receiving future
  libraries automatically.

## 7. Testing

### 7.1 UI fixtures (`lints/hyp_tracing/ui*/`)

Built with `--edition=2024` and `--extern tracing=…`, without `--test` except
where noted.

Default config (`ui/`), one assertion per fixture:

- `instrumented_sync.rs`, `instrumented_async.rs`, `instrumented_method.rs`,
  `instrumented_trait_default.rs`, `instrumented_trait_impl.rs`: silent.
- `plain_fn.rs`, `plain_method.rs`, `nested_fn.rs`: fire `uninstrumented_fn`.
- `const_fn.rs`, `closure_only.rs`, `trait_decl_only.rs`, `derive_only.rs`:
  silent. These are the §3 exclusions.
- `test_build.rs`: silent under `--test`. This needs its own harness
  invocation, because `rustc_flags` apply to a whole run.
- `allow_justified.rs`, `allow_module_level.rs`, `allow_crate_level.rs`,
  `allow_impl_level.rs`: silent.
- `allow_unjustified.rs`, `allow_empty_reason.rs`: fire the justification
  lint.
- `warn_level.rs`, `expect_level.rs`, `expect_unfulfilled.rs`,
  `deny_level.rs`: prove the level is resolved at the function.
- `local_macro_fn.rs`: a `macro_rules!` defined in the same crate that
  emits an uninstrumented `fn` does fire.

Config variants, each its own `#[test]` with `Test::dylint_toml(...)`:

- `ui_disabled/`: a plain function stays silent.
- `ui_disabled_no_reason/` (no `reason`) and `ui_disabled_blank_reason/`
  (`reason = "  "`): each gives exactly one justification diagnostic at the
  crate root, and no `uninstrumented_fn`.
- `ui_bad_config/` (`enable = false`): the config error, and nothing else.

Every fixture is checked to be load-bearing, as `ui/README.md` requires:
break the code it guards and confirm this fixture fails.

### 7.2 End to end

- New workspace `fixtures/tracing_consumer/` with `tracing` from crates.io and
  packages `good` (sync, async, method, trait default, all instrumented),
  `bad`, `exempt_ok` and `exempt_bad`. It pins the library by `path`, like
  `fixtures/consumer`. `scripts/e2e.sh` runs it with the same exact-set
  assertions.
- `fixtures/consumer/` and `fixtures/action_check/` get a `dylint.toml` that
  disables `hyp_tracing` with a reason. Their `add` functions would otherwise
  fire, and this runs the workspace switch through real `cargo dylint`.
- `ci.yml`'s "library actually loaded" loop, and `REQUIRED_LINTS` in
  `e2e.sh` and `release-check.sh`, gain the two new lint names.
- `release-check.sh`'s throwaway violating package also expects
  `uninstrumented_fn`, which proves `hyp_tracing` loads through a real
  `git`/`tag` pin. Its exempted package gets a crate-level justified `allow`.
